# 实验汇总报告

> **项目题目**：面向低资源编程语言仓颉的轻量级编译反馈修复方法研究  
> **编译器版本**：Cangjie Compiler 1.0.5 (`cjc` cjnative，Windows x86_64)  
> **基准数据集**：CangjieBench（HumanEval 164 题 + ClassEval 84 题，共 248 题）  
> **完成时间**：2026-11-16

---

## 一、环境与基线验证

1. **参考答案自检**：
   - HumanEval（164 题）：本地 `cjc 1.0.5` **164 / 164 (100.0%)** 通过。
   - ClassEval（84 题）：本地 `cjc 1.0.5` **82 / 84 (97.6%)** 通过（`id=35` 超时、`id=48` 编译错误）。
2. **论文数字复现**：
   - 使用 CangjieBench 公开的 `DeepSeek-V3_HumanEval.jsonl`（Syntax-Constrained），本地评测得到 **Pass@1 = 40.85%、Compile Rate = 47.56%**，与论文报告的 **40.9% / 47.6%** 完全一致，证明本地无 Docker 评测工具与官方沙箱完全等价。
3. **零成本报错挖掘**：
   - 扫描 CangjieBench 公开的 **6,647 个失败样本**，归纳出 **452 种 cjc 报错模板**（见 `results/error_stats.csv`）。据此构建了包含 16 条规则的「报错 → 仓颉正确写法」提示库（`src/repair_hints.py`），并实测修正了仓颉 1.0 API 变更（如 `ArrayList.append` 已更名为 `add`）。

## 三、研究问题（RQ）核心结论

### RQ1：多轮编译反馈修复能提升多少？几轮够用？
- **强模型（DeepSeek-V4.1-Flash）**：仅需 **2–3 轮** 即接近或达到饱和。`direct+hint` 从 68.29% 跃升至第 3 轮 **99.39%**；`syntax+hint` 从 93.29% 在第 2 轮即达到 **100.00%**；即使在更难的 ClassEval 上，`direct+hint` 也在第 1 轮就从 44.05% 跳到 **78.57%（+34.52%）**，第 5 轮达到 **91.67%**。
- **轻量模型（Doubao-Seed-2.0-Mini）**：提升幅度更大且持续到第 5 轮。`direct+hint` 从 9.76% 连续攀升至 **51.22%（翻了 5 倍以上）**；`syntax+hint` 从 44.51% 攀升至 **86.59%**。

### RQ2：哪种反馈最有效？（McNemar 精确检验）
1. **编译报错不可或缺**：两组模型上 `hint` 与 `raw` 相对 `blind`（只告知失败）均**全轮次统计显著**（DeepSeek R1–R5 $p = 0.0005 \text{–} 0.0433$；Doubao R1–R5 $p < 0.0001 \text{–} 0.0118$）。
2. **知识提示（`hint`）在轻量模型上优势显著**：在 Doubao-Seed-2.0-Mini 上，`hint` 比 `raw` 在 R5 高出 **+12.20 个百分点**（51.22% vs 39.02%，McNemar $p = 0.0017^*$），R1（$p = 0.0072^*$）和 R2（$p = 0.0294^*$）同样显著。
3. **强模型上的价值体现在收敛速度与 token 成本**：在 DeepSeek-V4.1-Flash HumanEval 上，`hint` 与 `raw` 最终都达到 99.39%，但 `hint` 第 3 轮即饱和（`raw` 需到第 5 轮），失败题平均修复轮数更少（1.24 vs 1.41 轮）。

### RQ3：成本—效果权衡（附插图）
- **加 `hint` 比加 `raw` 和 `blind` 更省钱**：
  - DeepSeek-V4.1-Flash：`hint`（1.06M tokens） < `raw`（1.11M） < `blind`（1.51M），`blind` 因盲修浪费了 **43%** 的额外 token 且准确率最低。
  - Doubao-Seed-2.0-Mini：`hint`（1.97M tokens, 51.22%） < `raw`（2.08M, 39.02%） < `blind`（2.89M, 13.41%）。
- **轻量模型 + 语法约束 + 知识修复可追平强模型 Agent**：Doubao-Seed-2.0-Mini 在 `syntax+hint` 下，第 4 轮达到 **84.76%**、第 5 轮达到 **86.59%**，追平并超过 CangjieBench 中 GPT-5 + Codex Agent 的 **84.8%**，全集仅消耗 2.17M tokens。

### RQ4：哪类错误最依赖知识提示？
以 Doubao-Seed-2.0-Mini 的第 0 轮失败样本为例：
- **API / 标识符缺失（`api_or_undeclared`）**：`blind` 16% → `raw` 48% → `hint` **79%**（提升最大，+31% over raw）。因为模型不知道仓颉标准库 API 的真实命名（如 `ArrayList.add` vs `append`），光看编译报错无法猜出正确替代品。
- **类型 / 可变性错误（`type_or_mutability`）**：`blind` 0% → `raw` 55% → `hint` **67%**。
- **外来语法（`foreign_syntax`）**：`blind` 3% → `raw` 27% → `hint` **38%**。
