# 修订实验方案（投稿前修订，预先设定）

本方案在修订实验（`results/revision/`）**开跑之前**写定并提交，提交时间以 git 记录为准。
起因：导师审阅投稿稿后指出，没有 15 次调用的固定反馈对照，就无法区分"Agent 自主检索有用"和"多给调用次数有用"；
另有 Kimi ClassEval direct 的 6 次运行在 Windows 上完成，与同格其他组的运行环境不同。
本方案是对 `docs/补充实验统计方案.md` 的**协议修订**，论文中须如实写明这些组和比较是投稿前追加的。

## 一、新增运行

协议与补充实验相同：temperature 0.3（Kimi 为 1.0）、每组 3 次重复、共享第 0 轮、提示 v2、ClassEval 每轮跑全部测试、`--strip-main`。
全部由 `src/run_matrix.py --matrix revision` 完成，结果写在 `results/revision/`，**不改动** `results/stage3/`、`results/review/` 的任何文件。

| 内容 | 模型 | 数据集 / 起点 | 组 | 第 0 轮 | 超时 |
|---|---|---|---|---|---|
| 固定反馈 15 轮 | Doubao-Seed-2.1-lite、GPT-6-Luna | ClassEval / direct | raw15、rag15 × 3 次 | `results/review/r0/` | 1800 秒 |
| 固定反馈 15 轮 | DeepSeek-V4.1-Flash | ClassEval / direct | raw15、rag15 × 3 次 | `results/stage3/r0/` | 1800 秒 |
| Linux 重跑 | Kimi-K3.1-Pro | ClassEval / direct | blind、agent × 3 次 | `results/review/r0/` | 1800 秒 |

- raw15、rag15 与 raw、rag 完全相同，只是最多修复 15 轮（15 次模型调用），与 agent15 的步数上限相同。rag15 用 BM25 固定检索（同 rag），不需要检索服务。
- 第 0 轮与同格已有的 raw、rag、agent、agent15 共享，保证逐题配对。
- 模型选择：按导师建议取 Doubao-Seed-2.1-lite、DeepSeek-V4.1-Flash、GPT-6-Luna，分属三家服务商、三个价格档。
  选择时已看过这三个模型的 agent15 结果，但**没有任何 15 轮固定反馈的结果**；论文中如实说明。
- Kimi 重跑全部在 Linux 上完成，替代原来在 Windows 上完成、ClassEval 48 题必然失败的 6 次运行。
- **运行环境**：全部修订运行都在 Linux 云主机上完成，与补充实验中的 agent15 一致。
  DeepSeek 的 raw、rag 来自第 3 阶段（Windows），因此 DeepSeek 的 B2、B4 是跨系统比较；
  写方案时已核对：这两组与 agent15 中 ClassEval 48 题在全部重复中都未通过。第四节第 3 条（去掉 48、53 题）同时作为这两个比较的跨系统敏感性分析。

## 二、新增比较族 B：调用预算（族内 Holm 校正）

每个模型（3 个）的 ClassEval direct 内做以下 4 个比较，共 12 个：

| 编号 | 比较 | 回答的问题 |
|---|---|---|
| B1 | agent15 vs raw15 | 同为 15 次调用，模型自主检索是否优于只给原始诊断（**主要比较**） |
| B2 | raw15 vs raw | 只给原始诊断时，调用上限从 5 放宽到 15 的收益 |
| B3 | agent15 vs rag15 | 同为 15 次调用，自主检索与每轮固定检索之比 |
| B4 | rag15 vs rag | 固定检索时，调用上限从 5 放宽到 15 的收益 |

- 检验方法与补充实验第二节相同：每题先求 3 次重复的平均通过率再求差；95% CI 按题 bootstrap（seed 0，10000 次）；
  p 值按题符号翻转置换检验（seed 0，10000 次），双侧。
- 族 G / A / R / I 的划分和各自的 Holm 不变；族 B 单独做 Holm。
- 结论的写法预先约定：B1、B3 都不显著时，只能说"在 15 次调用下未检出自主检索的优势"，不能说"两者等价"。

## 三、Kimi 重跑的替换规则

- 主分析：`kimik31p` ClassEval direct 的 blind、agent 改用 `results/revision/` 中的 Linux 重跑结果，
  涉及族 G（raw vs blind）与族 A（agent vs rag、agent15 vs agent）中这一格的比较；族 G、A 的 Holm 随之重算。
- 敏感性分析：同时报告用原来 Windows 运行时的结果，两者并列，不挑选。
- 原来的 6 次运行保留在 `results/review/`，不删除、不覆盖。

## 四、敏感性分析（不改变主结论的判定）

1. 族 B 与 G / A / R 合并成一个族做 Holm；
2. 去掉不稳定题（HumanEval 20、ClassEval 58）和每个比较中任一组超时的题后重算；
3. 再去掉已知缺陷题 ClassEval 48、53 后重算（同 `docs/补充实验统计方案.md` 第十节）；
4. 置换次数改为 100,000 次重算（同第十节）。

## 五、只做描述、不做检验的内容

- raw15、rag15、agent15 的逐轮累计通过率曲线（第 0–15 轮）；
- raw15、rag15 前 5 轮的累计通过率与已有 raw、rag 的 R5 对照，作为一致性检查；
- 含共享第 0 轮的"每解一题美元成本"；
- **服务端返回的模型标识**：修订运行起，每次调用记录 API 响应中的 `model` 字段（`served_models`）。
  报告每组返回标识的分布；若有与请求模型不一致的调用，列出涉及的题次，并去掉这些题次重算一次（敏感性分析）。
  之前的运行没有这一记录，无法补救，在论文局限性中说明。

## 六、纳入标准

与补充实验相同：summary 中 n = 84、errors = 0；Kimi 的 API 超时按未通过计入分母。

## 七、不做的事

## 八、零成本的事后分析（主结果已看过，一律标为事后 / 探索性）

以下只用现有数据，不调用模型，在报告中单独成节，不改变任何预先设定的判定：

1. **交互效应的天花板检验**：syntax × hint 交互只在 direct 与 syntax 两个起点第 0 轮都失败的题上重算，看交互是否仍然存在。
2. **rag2 离线选优的对半验证**：150 个查询随机对半（seed 0），在一半上选方案、在另一半上报告选中方案相对 BM25 的 hit@3 / nDCG@3。
3. **hint 规则来源**：若规则能追溯到构建它的任务，则只在未参与构建的任务上重算 hint 的效果；若无法追溯，在报告中说明。
4. **比较族划分对照**：各族分别 Holm 与全部合并 Holm 的显著比较数并列成表。
5. **延迟**：若日志中有逐次调用的时间，报告每组的平均耗时；没有则在局限性中说明。
