# 修订实验方案（投稿前修订，预先设定）

本方案在修订实验（`results/revision/`）**开跑之前**写定并提交，提交时间以 git 记录为准。
起因：导师审阅投稿稿后指出，没有 15 次调用的固定反馈对照，就无法区分"Agent 自主检索有用"和"多给调用次数有用"；
另有 Kimi ClassEval direct 的 6 次运行在 Windows 上完成，与同格其他组的运行环境不同。
本方案是对 `docs/补充实验统计方案.md` 的**协议修订**，论文中须如实写明这些组和比较是投稿前追加的。

全部由 `src/run_matrix.py --matrix revision` 完成，结果写在 `results/revision/`，**不改动** `results/stage3/`、`results/review/` 的任何文件。

| 内容 | 模型 | 数据集 / 起点 | 组 | 第 0 轮 | 超时 |
|---|---|---|---|---|---|
| 固定反馈 15 轮 | Doubao-Seed-2.1-lite、GPT-6-Luna | ClassEval / direct | raw15、rag15 × 3 次 | `results/review/r0/` | 1800 秒 |
| 固定反馈 15 轮 | DeepSeek-V4.1-Flash | ClassEval / direct | raw15、rag15 × 3 次 | `results/stage3/r0/` | 1800 秒 |
| Linux 重跑 | Kimi-K3.1-Pro | ClassEval / direct | blind、agent × 3 次 | `results/review/r0/` | 1800 秒 |

- Kimi 重跑全部在 Linux 上完成，替代原来在 Windows 上完成、ClassEval 48 题必然失败的 6 次运行。

## 二、新增比较族 B：调用预算（族内 Holm 校正）

每个模型（3 个）的 ClassEval direct 内做以下 4 个比较，共 12 个：

| 编号 | 比较 | 回答的问题 |
|---|---|---|
| B1 | agent15 vs raw15 | 同为 15 次调用，模型自主检索是否优于只给原始诊断（**主要比较**） |
| B2 | raw15 vs raw | 只给原始诊断时，调用上限从 5 放宽到 15 的收益 |
| B3 | agent15 vs rag15 | 同为 15 次调用，自主检索与每轮固定检索之比 |
| B4 | rag15 vs rag | 固定检索时，调用上限从 5 放宽到 15 的收益 |

- 检验方法与补充实验第二节相同：每题先求 3 次重复的平均通过率再求差；95% CI 按题 bootstrap（seed 0，10000 次）；
  p 值按题符号翻转置换检验（seed 0，10000 次），双侧。
- 族 G / A / R / I 的划分和各自的 Holm 不变；族 B 单独做 Holm。
- 结论的写法预先约定：B1、B3 都不显著时，只能说"在 15 次调用下未检出自主检索的优势"，不能说"两者等价"。

## 九、开跑前追加：GPT-6-Luna 换渠道与一致性判定（2026-11-27）

本节在修订实验任何一组开跑之前追加并提交；写定时没有任何 15 轮固定反馈的结果。

- **起因**：GPT-6-Luna 已有各组（raw、rag、agent、agent15 等）都经 AMR 中转（open-design）完成，该渠道额度已用完。
  修订实验中 GPT-6-Luna 的 6 组（raw15、rag15 × 3 次）改用另一个有额度的 OpenAI 兼容渠道；
  渠道名称、地址与 Key 尾号在开跑时记入 `docs/实验偏离记录.md` 第 7 节。
- **做法**：不改代码，只在运行前把环境变量 `AMR_BASE_URL`、`AMR_API_KEY` 指向新渠道；请求的模型名仍为 `gpt-6-luna`。
- **影响范围**：族 B 中 GPT-6-Luna 的 B1–B4 全部成为跨渠道比较（raw、rag、agent15 来自原渠道，raw15、rag15 来自新渠道）；
  其他族与已有结果不受影响。

**判定规则（预先设定）**：GPT-6-Luna 的 6 组同时满足以下 4 条，判为「渠道一致」。

1. 每组 `served_models` 只含 `gpt-6-luna` 或以它开头的带版本号标识；
2. 每组 `temperature_used` 为 `[0.3]`；
3. 6 组在同一渠道上完成（中途再换渠道即不满足）；
4. 前 5 轮一致性：每题取 raw15 三次重复中「前 5 轮内通过」（`passed` 且 `rounds_used` ≤ 5）的平均，
   减去已有 raw 三次重复的平均通过，按 84 题求均值与 95% CI（按题 bootstrap，seed 0，10000 次）；
   要求 CI 包含 0 且均值的绝对值不超过 5 个百分点。rag15 与 rag 同样计算，两项都须满足。
   5 个百分点约为 4 题，略大于已有 raw 三次重复 R5 的极差（58.33–61.90，3.6 个百分点）。

- **判为一致**：按第二节，族 B 为 3 个模型共 12 个比较，族内 Holm。
- **判为不一致**（任一条不满足）：主分析的族 B 只含 DeepSeek-V4.1-Flash 与 Doubao-Seed-2.1-lite 的 8 个比较，族内 Holm；
  GPT-6-Luna 的 B1–B4 作为敏感性分析单独报告并注明跨渠道。第四节第 1 条的合并 Holm 也按主分析的族 B 计算。
- 无论判定结果如何，第 4 条的两个差值与 CI 都在报告中列出；判为不一致时写明是哪一条不满足。

## 十一、渠道指纹检查（2026-11-28 写定，全部修订实验结束后执行）

本节在执行任何指纹调用之前写定。目的：用可复查的数据确认实验中不同渠道调用的是同一个模型。

- **检查的渠道对**：
  1. DeepSeek-V4.1-Flash：火山方舟（`deepseek-v4-1-flash-261017`）vs DMXAPI（`deepseek-v4.1-flash-1017`）；
  2. GPT-6-Luna：AMR 中转（open-design）vs MyUSAPI（均为 `gpt-6-luna`）。
  - 火山方舟 Coding Plan 与 Agent Plan 不检查：同一服务商的两个端点，官方确认为同一模型。
- **做法**（`src/channel_fingerprint.py`，不改实验代码）：取 ClassEval 题号排序后的前 10 题，请求与实验第 0 轮相同（system + direct 首条提示），
  另加 `max_tokens = 20`、`logprobs`（top 5）、`temperature = 0`；每个渠道每题调用 2 次。Key 只从环境变量读取，输出（`results/fingerprint/`）不含 Key 与地址。
- **判定（预先设定）**，每个渠道对：
  - C1：10 题的 `prompt_tokens` 两边全部相同（必须满足）；
  - C2：两边都返回 logprobs 时，跨渠道公共前缀上所选 token 的 |logprob 差| 的中位数 < 0.05；
  - C3：跨渠道"返回的 20 个 token 完全相同"的比例，不低于两个渠道各自两次调用之间该比例的较小值减 0.2。
  - C1 满足且 C2、C3 均未判为不满足（不适用时记"不适用"），判为「指纹一致」。
- **结果的用法**：
  - 指纹一致：论文中写"指纹检查支持同一模型"，并报告 C1–C3 的数值；第九、十节的处理不变。
  - 指纹不一致：如实写入局限，并写明是哪一条不满足；DeepSeek 的处理（第十节）与 GPT-6-Luna 的判定（第九节）另行讨论，讨论结果记入 `docs/实验偏离记录.md`。
  - 一方不返回 logprobs 时，C2 记"不适用"，结论注明证据较弱（只有 token 计数与文本对照）。
- **执行时的补记（2026-11-28，在本机执行，未等全部实验结束；第一作者决定提前执行）**：
  1. GPT-6-Luna 改为不设 `max_tokens`：它是推理模型，20 个 token 内只做内部推理、返回空 choices；此改动在任何比较之前作出。
     AMR 不接受 `logprobs` 参数（返回笼统的 400），脚本改为带 logprobs 的请求失败即去掉 logprobs 重试。
  2. 火山方舟一侧用 Agent Plan（本机 Coding Plan 的 Key 月度额度已用完），请求的模型名仍为 `deepseek-v4-1-flash-261017`。
  3. C3 对两个模型都没有区分力：DeepSeek 的输出以推理文字开头，GPT 输出完整回答，temperature = 0 时同一渠道两次调用也不相同，
     "完全相同"的比例处处为 0，C3 必然满足。因此事后补充两项描述性指标（不参与判定，写入 `compare` 输出的 `descriptive`）：
     上下文相同的位置上 top-5 分布的重合率、top-1 一致率与 |logprob 差|；每次调用的输出 token 数中位数。
- **结果**（`results/fingerprint/`）：
  - DeepSeek（火山 vs DMXAPI）：C1、C2、C3 均满足，判为「指纹一致」。C2 的中位数跨渠道 0.0029，渠道内 0.0029 / 0.0027。
    描述性：top-1 一致率跨渠道 0.93、渠道内 0.96 / 0.96；top-5 重合率 0.79 vs 0.84 / 0.91；共有候选的 |logprob 差| 中位数 0.74 vs 0.42 / 0.37。
    跨渠道差异略大于渠道内波动，与「同一模型、部署（精度、硬件或批处理）不同」相符，10 题不足以排除细微的版本差异。
  - GPT-6-Luna（AMR vs MyUSAPI）：C1 满足，C2 不适用（两边都不返回 logprobs），C3 满足但无区分力，按规则判为「指纹一致」，证据较弱。
    描述性：每次调用的输出 token 中位数 AMR 3123、MyUSAPI 1024；实验数据中 AMR 的 raw / rag 每次修复调用约 1800、MyUSAPI 的 raw15 / rag15 约 960。
    推测两个中转站默认的推理配置不同（请求中未设推理强度）。第九节第 4 条：raw15 vs raw −0.40（CI −2.38, +1.19），rag15 vs rag −3.17（CI −7.14, +0.40），4 条均满足。
- **按本节与第九节的规则**，DeepSeek、GPT-6-Luna 的族 B 都留在主分析。论文中写"渠道检查支持同一模型"，并报告上述描述性差异，不写"完全相同"；
  GPT-6-Luna 跨渠道的成本比较（每解一题美元成本）不直接比较，单独注明。

## 十二、GPT-6-Luna 族 B 统一到 MyUSAPI（2026-11-28 写定，补跑开始之前）

- **起因**：第十一节发现 MyUSAPI 每次修复调用的输出 token 约为 AMR 的一半（约 960 vs 约 1800），推测默认推理配置不同。
  族 B 中 GPT-6-Luna 的 B1、B3（agent15 vs raw15 / rag15）两边分属 AMR 与 MyUSAPI，推理量差约一倍，比较结果无法与渠道差异分开。
  写定本节时已看过 raw15、rag15 的结果与第九节第 4 条的数值，没有看过任何 B1–B4 的比较结果。
- **做法**：在 MyUSAPI 上补跑 ClassEval direct 的 raw、rag、agent15 各 3 次（共 9 组），参数与 `results/review/` 中同名组完全相同
  （轮数、temperature 0.3、`--all-tests`、`LLM_TIMEOUT`），从 `results/review/r0/` 的共享第 0 轮开始，输出到 `results/revision/`（组名与 review 中相同，以目录区分）。
  9 组在同一渠道、同一 Key 上连续跑完；并发不超过 `-p 2 -j 4`。
  - **补跑开始后、第 1 组确认前修改（2026-11-28）**：为提速，其余 8 组按**整组**分到两台 Linux 主机，同用 MyUSAPI `***09009`：
