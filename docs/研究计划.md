**我们的定位**：免训练、低成本、可复现。把一次生成和 Agent 之间的空白补上，并给出"反馈形式 × 轮数 × 成本"的系统分析。

## 2. 研究问题（RQ）

- **RQ1 修复有没有用、几轮够用？** 在语法约束提示的基础上，加 1–5 轮编译反馈修复，pass@1 随轮数怎样变化？在第几轮饱和？
- **RQ2 什么样的反馈最有效？** 消融实验比较：
  - `blind`：只告诉模型"错了"（对照组，排除"多试几次"本身带来的提升）
  - `raw`：原始 cjc 报错
  - `hint`：报错 + 规则匹配出的仓颉知识提示（我们的方法）
- **RQ3 性价比怎么样？** 每道通过的题平均花多少 token / 多少钱？和 CangjieBench 里的 Agent 比，效果差多少、省多少？
- **RQ4 哪些错误修得好、哪些修不好？** 按错误类别（外来语法 / API 臆造 / 类型 / 逻辑）统计修复成功率。
- （可选）**RQ5 小模型行不行？** 本地 7B 模型（如 Qwen2.5-Coder-7B，用 Ollama 运行）加上修复循环，能不能追上不修复的大模型？

## 3. 实验设计

- **数据集**：CangjieBench HumanEval 子集，164 题（先做这个）；时间充裕再加 ClassEval 84 题（需要 stdx 库）
- **模型**（选 2–3 个便宜的）：DeepSeek-V3.x（`deepseek-chat`）、Qwen 系列（阿里云百炼或硅基流动的免费额度）、GLM-4-Flash（免费），可选本地 Ollama 小模型
- **变量**：提示 {direct, syntax} × 反馈 {blind, raw, hint} × 轮数上限 5（一次跑到 5 轮，就能画出 0–5 轮的曲线）
- **指标**：pass@1（按轮次累计）、编译通过率、token 数 / 费用、平均修复轮数
- **温度**：0（保证可复现）
- **预算估算**：164 题 × 平均约 3 次调用 × 约 6k tokens ≈ 3M tokens/组。按 DeepSeek 当前价格，每组只需几元到十几元，全部实验 **< 100 元**（以官网实时价格为准）

## 6. 需要注意的效度问题（写进论文的 Threats to Validity）

- **规则过拟合**：规则是从同一个基准的失败样本里挖出来的。缓解办法：规则只从 **CangjieBench 公开的其他模型** 的结果里挖，然后在**我们自己新跑的模型**上测试；或者把 164 题按 5:5 切分，一半用来挖规则，一半用来评测
- **数据污染**：新模型可能已经见过 CangjieBench（2026 年 3 月公开）
- **`--init` 热启动**：第 0 轮来自旧模型，后续修复用的是新模型，两者不是同一个模型。正式实验最好都从头生成
- **测试判定**：沿用官方判定（stdout 中出现 "fail" 即判失败），与论文口径一致
