# 留出测试评测方案（Original-30，预先设定）

本方案在用留出测试评测**任何**模型代码之前写定并提交，提交时间以 git 记录为准。
写定时只做过入库检查（参考答案、常量返回、去重，见 `data/original30/README.md`），没有用留出测试运行过任何模型生成的代码。

## 一、要回答的问题

修复过程中，模型看到的测试反馈与最终判定是否修好用的是同一套测试，"修好"只能说明通过了这套测试。
本评测回答：**修复后通过原测试的代码，在修复过程中从未使用过的留出测试上是否仍然正确；
修复得到的通过是否比第 0 轮直接通过更容易在留出测试上失败（即是否存在拟合反馈测试的迹象）。**

## 二、评测对象与方式

- **评测对象**：进入现有 Original-30 统计的全部运行的每题最终代码（记录中的 `solution` 字段），包括：
  - `results/original30/runs/` 与 `results/review/runs/` 中 `*_or_*` 的全部修复组（各模型、两个起点、各反馈方式、各次重复）；
  - `results/original30/r0/`、`results/review/r0/` 中 `*_or_*` 的第 0 轮代码。
  - 不含 `pilot/`、`superseded/` 中的文件；组的纳入标准与现有统计相同（n = 30 且 errors = 0）。
- **评测方式**：在同一台机器（本机，Windows，cjc 1.0.5）上，每个代码分别与原测试（`test` 字段）、留出测试拼接后编译运行一次，
  判定口径与主实验相同（`runner.compile_and_run`：编译 60 秒、运行 10 秒超时，stdout 出现 `fail` 即测试失败）。
  原测试也在本机重跑，使两种测试的结果来自同一环境、可逐题配对；同时报告本机原测试结果与记录中 `passed` 的一致率。
- **超时**：任一测试出现超时（`failure_kind = timeout`）时重跑，最多共 3 次，取最后一次；仍超时按未通过计，并报告超时题次数。
- **没有代码的题次**（API 报错等，记录中无 `solution`）：两种测试都按未通过计，与主分析一致。
- 不调用任何模型 API；评测在本机运行，不占用正在运行修订实验的主机。
- 运行前核对 `heldout_tests.jsonl` 的 SHA-256（按 LF 换行）为 `311567ce46a5330f90ac16890dd578f05c009b3730e68103c1f73731a1542bd2`，不一致则停止。

## 三、主要分析（预先设定）

记号：对一个题次（某组、某次重复、某题），O = 本机原测试通过，H = 留出测试通过。
「修复通过」= O 且 `rounds_used` ≥ 1；「第 0 轮通过」= O 且 `rounds_used` = 0（第 0 轮文件中的题次按 `rounds_used` = 0 计）。

1. **留出失败率**：在 O 的题次中 H 不通过的比例，分别对「修复通过」与「第 0 轮通过」计算。
   第 0 轮通过的代码从未见过任何测试反馈，它的留出失败率反映测试本身覆盖不全，作为基线。
2. **主要比较**：留出失败率（修复通过）− 留出失败率（第 0 轮通过），合并全部修复组与模型。
   95% CI 按题做整群 bootstrap（以题为单位重抽 30 题，seed 0，10,000 次）。
3. **结论写法预先约定**：
   - CI 包含 0：写"未检出修复拟合反馈测试的证据"，并报告两个失败率；不写"不存在拟合"。
   - CI 全部大于 0：写"修复得到的通过中，有 X% 在留出测试上失败，高于第 0 轮通过的 Y%"，并在讨论中说明修复成功率含有拟合反馈测试的成分。
   - CI 全部小于 0：如实报告，不作额外解释。

## 四、次要分析（报告，不改变主结论的判定）

1. **每组的两种通过率**：按模型 × 起点 × 反馈方式列出原测试（本机）与留出测试的通过率（3 次重复取均值 ± 标准差）。
2. **按反馈方式分**：分别计算 blind 与其余反馈方式（raw、hint、rag、rag2、agent、agent15）「修复通过」的留出失败率。
   blind 的修复提示只说明"未编译通过或未通过测试"（`prompts.REPAIR_BLIND`），不提供具体的失败测试，可作为"能否看到失败测试"的对照；只做描述，不做检验。
3. **以留出测试为结果重算已有比较**：Original-30 上已有的两两比较（`results/stats/original30_stats.md` 与 `review_stats` 中数据集 `or` 的各族比较），
   把结果改为"原测试与留出测试都通过"重算，方法、比较族与 Holm 校正方式不变；与原结果并列报告，标注为敏感性分析。
4. **去掉题意边界题**：去掉 1014、1022、1027 三题后重算第三节第 2 条（新测试已避开这些题的歧义输入，主分析保留全部 30 题）。

## 五、输出

- 逐题次结果写入 `results/heldout/`（每个题次一行：来源文件、组名、题号、`rounds_used`、O、H、超时次数）；
- 统计写入 `results/stats/heldout_stats.{md,json}`，并加入 `src/reproduce_offline.py`（只读逐题次结果，离线可复现；重新编译运行不属于离线复现的范围）。

## 六、局限（写入论文）

- 只有 Original-30（30 道函数级题）有留出测试；ClassEval 与 HumanEval 只有一套测试，其结论仍应表述为"通过基准测试的比例"。
- 留出测试由两人编写与审核，每题 10 个，仍可能覆盖不全；第 0 轮通过的留出失败率即用于衡量这一点。
- 编写人报告的 3 道题意边界题未改动题目，新测试已避开相关输入。
- A2、R2 未参与实验、未看过模型生成的代码或实验结果（第一作者于 2026-11-27 确认）。
