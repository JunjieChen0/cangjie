# 补充实验统计方案（预先设定）

本方案在补充实验（`results/review/`）**正式结果出来之前**写定并提交，提交时间以 git 记录为准。
实现见 `src/review_stats.py`；方案之外的任何分析在报告中一律标为「事后 / 探索性」。

## 一、数据与配对规则

| 模型 | 修复组来源 | 第 0 轮 |
|---|---|---|
| GLM-5.3-Flash、Doubao-Seed-2.1-lite、U2-Flash | `results/review/` | review 自己生成 |
| Kimi-K3.1-Pro | `results/review/`（重新跑的完整矩阵） | review 自己生成 |
| DeepSeek-V4.1-Flash、Doubao-Seed-2.0-mini | 原有组取自 `results/stage3/`、`results/original30/`；agent / agent15 / rag2 取自 `results/review/` | 复用第 3 阶段与 Original-30 的共享第 0 轮 |
| DeepSeek ClassEval syntax | `results/review/` | review 自己生成 |

- 同一个比较中的两组必须共享同一份第 0 轮，才能逐题配对。
- 第 3 阶段原有的 Kimi 数据（方舟、600 秒超时、只有 4 组）**不与** review 中的 Kimi 数据合并，也不互相比较。
- 纳入标准与第 3 阶段相同：summary 中 n 等于题数、errors = 0；Kimi 的 API 超时按未通过计入分母（GLM-5.3-Flash 见第八节）。

## 二、检验方法（与第 3 阶段相同）

- 每道题先求 3 次重复的平均通过率，再求两组之差；
- 95% CI：按题 bootstrap（seed 0，10000 次）；p 值：按题符号翻转置换检验（seed 0，10000 次）；
- 逐次重复的 McNemar p 值只作稳健性参考。

## 三、比较族（各族分别做 Holm 校正）

补充实验回答三个独立的问题，每个问题一个比较族，各自做 Holm 校正（α = 0.05）。
第 3 阶段（33 个比较）与 Original-30（17 个比较）的结论和校正不受影响。

**族 G：结论能否推广到其他模型。**
模型：GLM-5.3-Flash、Doubao-Seed-2.1-lite、U2-Flash、Kimi-K3.1-Pro（重跑）；另加 DeepSeek ClassEval syntax。
每个「模型 × 数据集 × 起点」内的比较与第 3 阶段相同：
hint vs raw、rag vs raw、rag vs hint、raw vs blind；HumanEval direct 另有 hint_co vs raw_co、rag_co vs raw_co。

**族 A：Agent 基线。**
全部 6 个模型、每个有 Agent 组的「模型 × 数据集 × 起点」内：
- agent vs rag：同样最多 5 次模型调用、同样能用文档，比较「模型自己决定何时检索」与「每轮固定检索」；
- agent15 vs agent：步数从 5 放宽到 15 的收益。

**族 R：改进检索 rag2。**
全部 6 个模型、每个有 rag2 组的「模型 × 数据集 × 起点」内：rag2 vs rag。

## 四、敏感性分析（不改变主结论的判定）

1. 三族合并成一个族做 Holm；
2. 去掉判定不稳定的题（HumanEval 20、ClassEval 58）和每个比较中任一组超时的题后重算。

## 五、只做描述、不做检验的内容

- 6 个模型 × 全部条件的通过率主表（R0、R5 均值 ± 标准差、逐轮曲线）；
- 成本：含共享第 0 轮的「每解一题美元成本」；rag2 每轮的查询改写调用按改写模型单价计入；
- Agent 行为：每题平均检索次数、至少检索一次的题占比、无效动作次数、实际用掉的步数。

## 六、syntax × hint 交互效应（2026-11-19 追加，补充实验正式结果出来之前）

问题：给了语法参考手册（syntax 起点）之后，hint 的作用是否变小（两者是否互相替代）。

- 每个「模型 × 数据集」内、每道题：I = (hint − raw)<sub>direct</sub> − (hint − raw)<sub>syntax</sub>，
  其中每项为该组 3 次重复的平均通过率；I > 0 表示有语法手册时 hint 的增益更小。
- 只用四组都有的题；95% CI 按题 bootstrap，p 值按题符号翻转置换检验（同上，seed 0，10000 次）。
- **验证性族 I**（数据尚未看过）：GLM-5.3-Flash、Doubao-Seed-2.1-lite、U2-Flash、Kimi-K3.1-Pro（重跑）
  × HumanEval / ClassEval / Original-30，族内 Holm 校正。
- **探索性**（数据已在第 3 阶段与 Original-30 中看过，不作验证性结论）：DeepSeek-V4.1-Flash、Doubao-Seed-2.0-mini
  × HumanEval / ClassEval / Original-30（DeepSeek ClassEval 的 syntax 半边来自 review），单独做 Holm 并标为事后分析。

## 七、不做的事

- 不按结果挑选「每格最优固定策略」再与 Agent 比较（会引入选择偏差）；
- 不把不同第 0 轮的组放在一起配对比较；
- 某组最终没跑完时如实报告缺失，不补写、不插补。

## 八、GLM-5.3-Flash 收尾规则（2026-11-24 追加，下列各格结果统计之前）

背景：GLM-5.3-Flash 在 ClassEval 上平均每题输出约 17 万 tokens，单次请求常超时（1800 秒，每次调用重试 5 次），
按原计划全部跑完还需 1–2 天，时间与成本已远超预期。

1. **补跑次数封顶**：每组正常跑完一次后，对出错的题用续跑补跑一次；补跑后仍为 API 超时的题按未通过计入分母
   （口径同 Kimi，实现为 `review_stats.REVIEW_TIMEOUT_AS_FAIL`，只用于 review 的组）。限流等非超时错误与模型无关，
   继续补跑，直到剩下的错误全部是超时。
2. **放弃一格**：GLM-5.3-Flash × ClassEval × syntax × rag2（3 次重复）不再运行，在结果中如实列为缺失（见第七节）。
   选这一格的理由只看设计：在尚未开始的格子中，它只参与族 R 的 1 个比较（rag2 vs rag），放弃后损失的预定比较最少；
   另一候选 ClassEval × syntax × rag 参与族 G、A、R 共 4 个比较，照常跑完 3 次重复。
   决定时，这两格的 GLM 结果都没有统计过（syntax rag 只有第 1 次重复跑了一部分，syntax rag2 尚未开始）；
   族 R 其他模型的中期结果此前已看过，因此本条不以任何中期结果为依据。
3. **不设截止时间**：其余组按第 1 条全部跑完。若因平台故障、账号停用等外部原因无法继续，如实记录，整组列为缺失。
4. **敏感性分析**：第四节第 2 条（去掉每个比较中任一组超时的题后重算）同样适用于 GLM。

## 九、GLM-5.3-Flash ClassEval syntax 的第 0 轮分裂（2026-11-25 追加，补充实验统计结果出来之前）

合并三台云主机的数据后，`run_matrix.py --check` 发现这一格有两份第 0 轮：本地 11-22 生成的一份，
与 Aliyun 11-23 重新生成的一份（30 题判定不同）。按修复组记录的第 0 轮逐题对照，blind、raw、hint、agent、
rag（Aliyun 上跑的 3 次重复）共 15 组用的是 Aliyun 那份；agent15 的 3 组用的是 11-22 那份。

1. **以 Aliyun 那份为这一格的共享第 0 轮**，rag 第 2、3 次重复用 Aliyun 跑出的版本
   （此前合并时被另一台机器的版本覆盖）；被替换的文件移到 `results/review/superseded/` 留档。
   选择只看「是否与同格其他组共享第 0 轮」，不看错误数或通过率。
2. **agent15 三组不参与配对比较**（第一、七节），即族 A 中 GLM ClassEval syntax 的 agent15 vs agent 不做，
   如实列为缺失；三组通过率照常列入描述表。实现为 `review_stats.R0_SPLIT`。
3. Aliyun 版 rag 第 2、3 次重复中分别有 3、1 道超时题没有做第八节第 1 条的补跑，直接按未通过计入，并由第四节第 2 条的敏感性分析覆盖。
